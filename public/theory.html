Theory and design

Problem definition, formal model, algorithms, complexity, architecture and validation of Automata Studio — the design evidence for the M1 review. Tables marked “live” are generated by the engine, so they always match the code.

1. Problem definition and objectives

ProblemStudents find subset construction hard to follow on paper: ε-closures are missed, subsets are recomputed, and the dead state is forgotten. Static diagrams do not show why each DFA state exists.
InputAn ε-NFA N = (Q, Σ, δ, q₀, F) as text, as a transition table, or as a regular expression (converted by Thompson's construction); a DFA for minimisation; strings to test.
OutputAn equivalent DFA D with L(D) = L(N), every intermediate step, the minimal DFA, string traces, and a verification that the languages match.
Objectives(1) Make each step of subset construction visible and replayable at any speed. (2) Validate input and handle every edge case with a clear message. (3) Prove results correct by automated equivalence checks. (4) Support learning through Bloom-levelled practice, timed exams and an AI tutor.

2. Formal model

MachineTransition functionAcceptance
DFA (Q, Σ, δ, q₀, F)δ : Q × Σ → Qthe single run ends in F
NFA (Q, Σ, δ, q₀, F)δ : Q × Σ → 2^Qsome run ends in F
ε-NFA (Q, Σ, δ, q₀, F)δ : Q × (Σ ∪ {ε}) → 2^Qsome run, with ε-moves taken freely, ends in F

Subset construction builds D = (Q_D, Σ, δ_D, ε-closure({q₀}), F_D) where Q_D ⊆ 2^Q contains only reachable subsets, δ_D(S, a) = ε-closure(move(S, a)), and F_D = { S ∈ Q_D : S ∩ F ≠ ∅ }.

3. Algorithms

ε-closure(S):                                   // stack-based, handles ε-cycles
  result ← S; stack ← S
  while stack not empty: q ← pop
    for p in δ(q, ε): if p ∉ result: add p to result; push p
  return result

SubsetConstruction(N):
  D0 ← ε-closure({q0}); Dstates ← [D0]; i ← 0
  while i < |Dstates|:                          // breadth-first: Dstates is also the queue
    S ← Dstates[i]
    for a in Σ (sorted):
      T ← ε-closure( ∪ { δ(q, a) : q ∈ S } )    // T = ∅ is the dead state
      if T ∉ Dstates: append T                  // stop if |Dstates| > 300
      δD(S, a) ← T
    i ← i + 1
  F_D ← { S ∈ Dstates : S ∩ F ≠ ∅ }

Minimise(D):                                    // table filling (Myhill–Nerode)
  remove states unreachable from q0; send missing transitions to a new trap state
  mark (p, q) when exactly one of p, q is final                    // round 0
  repeat: mark (p, q) if for some a, (δ(p,a), δ(q,a)) was marked in an earlier round
  until a round marks nothing; merge every unmarked pair

Thompson(r):  a → two states and one a-arrow;  r1 r2 → ε from end of r1 to start of r2;
              r1 | r2 → new start/end with ε to/from both;  r* → new start/end, ε to skip and to repeat

4. Complexity

OperationTime (n NFA states, k symbols)Note
ε-closure of one setO(n + m_ε)each state pushed at most once
Subset constructionO(2ⁿ · k · n²) worst caseusually far fewer reachable subsets; capped at 300 DFA states
Simulating an NFA on wO(|w| · n²)tracks the active set, no backtracking
Table-filling minimisationO(r · s² · k)s DFA states, r rounds ≤ s
Equivalence checkO(p · k)p reachable pairs of subsets; returns the shortest counter-example

Correctness. By induction on |w|: after reading w, the DFA is in exactly the set of NFA states reachable on w (with ε-moves). Hence D accepts w iff that set meets F, i.e. iff N accepts w. The Test Suite checks this exhaustively on every short string for every test automaton.
