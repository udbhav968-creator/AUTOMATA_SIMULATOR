Theory & Design (M1 evidence)

Problem definition, formal model, algorithm, complexity and design. Everything on this page is rendered from the same engine the simulator uses.

1 · Problem definition

Input: an ε-NFA N = (Q, Σ, δ, q₀, F). Output: an equivalent DFA D with L(D) = L(N), plus every intermediate step. Objective: make subset construction visible, verifiable and testable.

δ : Q × (Σ ∪ {ε}) → 𝒫(Q). The DFA states are subsets of Q; its start state is ε-closure({q₀}); a subset is accepting iff it contains a state of F.

2 · Algorithm (pseudocode)

ε-closure(S): stack ← S; result ← S
  while stack not empty: pop q; for p in δ(q, ε): if p ∉ result: add p; push p
  return result

SubsetConstruction(N):
  D0 ← ε-closure({q0}); Dstates ← [D0]; queue ← [D0]
  while queue not empty:
    S ← dequeue
    for each a in Σ:
      T ← ε-closure( ∪ δ(q, a) for q in S )     // T may be ∅ → dead state
      if T ∉ Dstates: add T, enqueue T
      δD(S, a) ← T
  F_D ← { S in Dstates : S ∩ F ≠ ∅ }

Complexity: at most 2n DFA states, each with |Σ| transitions → O(2n · |Σ| · n²) worst case. The simulator therefore limits the NFA to 16 states and the DFA to 300 states, and says so clearly.

Correctness idea: by induction on |w|, after reading w the DFA is in exactly the set of NFA states reachable on w. The Test Suite checks this exhaustively on all short strings.
